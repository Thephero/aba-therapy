PART A — GET THE APP RUNNING LOCALLY

-----------------------

----------------------------------
1. Go to https://dashboard.stripe.com
2. Turn ON the "Test mode" toggle (top-right of the dashboard).

3. Developers -> API keys -> copy the "Secret key"
   It looks like:  sk_test_...

B3. CREATE THE TEST WEBHOOK (only needed for REMOTE testing on Render)
----------------------------------------------------------------------
1. Still in Test mode: Developers -> Webhooks -> "Add endpoint"
2. Endpoint URL:
   https://aba-therapy-backend-7l47.onrender.com/api/v1/webhooks/stripe
3. Select these events:
       checkout.session.completed
       customer.subscription.updated
       customer.subscription.deleted
       invoice.payment_failed
   (invoice.paid is optional — the app treats it as a stub for now.)
4. Click "Add endpoint" -> copy the "Signing secret"
   It looks like:  whsec_...

B4. PUT THE KEYS IN THE APP
---------------------------
CHOICE 1 — LOCAL testing (recommended first):
    Open the file:  aba-backend/.env
    Add these lines (paste YOUR values):

        STRIPE_SECRET_KEY=sk_test_...

    ⚡ Optional legacy vars (no longer required — the app auto-creates
       prices; only needed if you want portal upgrades to auto-map
       tier names):
        STRIPE_PRICE_BASIC_MONTHLY=price_...
        STRIPE_PRICE_BASIC_ANNUAL=price_...
        STRIPE_PRICE_PRO_MONTHLY=price_...
        STRIPE_PRICE_PRO_ANNUAL=price_...
        STRIPE_PRICE_ENTERPRISE_MONTHLY=price_...
        STRIPE_PRICE_ENTERPRISE_ANNUAL=price_...

    (No webhook secret needed locally IF you run Stripe CLI — see B5.)
    Restart the backend after saving (Ctrl+C, then npm run dev again).

CHOICE 2 — REMOTE testing on the live site:
    Go to https://dashboard.render.com -> your backend service
    -> Environment -> add the SAME variables as above, PLUS:

        STRIPE_WEBHOOK_SECRET=whsec_...   (from step B3)

    -> Save changes (this redeploys automatically).
    Also push the new DB columns once:
    Render -> Settings -> Build Command, change to:

        npm ci --include=dev && npm run db:generate:prod && npm run db:push:prod && npm run build

B5. LOCAL WEBHOOK FORWARDING (only for local testing)
-----------------------------------------------------
The Stripe CLI lets local webhooks work:

1. Install:  https://github.com/stripe/stripe-cli/releases/latest
   (Windows: download the .zip, unzip, use stripe.exe)
2. Login:        stripe login
3. Forward:      stripe listen --forward-to localhost:3001/api/v1/webhooks/stripe
4. It prints:    whsec_...   ->  paste this into aba-backend/.env as:
                 STRIPE_WEBHOOK_SECRET=whsec_...
5. Keep that terminal OPEN while testing, then restart the backend.

TIP: You can skip B5 for a first quick test — checkout + activation
still works; webhook events (renewals/cancellations) just won't sync
until you run it.

B6. RUN THE TEST
----------------
1. Start the app (Part A) or use the live site.
2. Login as Admin -> click "Billing" in the sidebar.
3. Pick a plan (e.g. Basic, Monthly) -> "Subscribe".
4. Stripe Checkout opens (test mode). Pay with a TEST CARD (Part C).
5. You return to the Billing page -> plan shows "Active".
6. "Manage billing" opens the Stripe Customer Portal
   (change card, cancel, see invoices).

PART D — WHEN SOMETHING DOESN'T WORK
=====================================================================

- "Payments are not configured on the server"
      -> STRIPE_SECRET_KEY is missing/empty in the .env (or on Render).
         Restart the backend after saving .env.

- "Stripe price ... is not configured"
      -> ⚡ Legacy message (Oct 15 update): prices now auto-create from
         the platform pricing config, so this should not appear.
         If you still see it, try setting STRIPE_PRICE_<plan>_<cycle>
         (spelling matters) — or just make sure STRIPE_SECRET_KEY is
         set correctly.

- Checkout opens but payment fails
      -> Make sure you used a TEST card (Part C) and that Stripe
         dashboard is in TEST mode (keys start with sk_test_).
         Mixed keys (sk_live_ + test cards) always fail.

- Payment OK but Billing page still shows trial
      -> Webhook not connected. Locally: run stripe listen (B5).
         On Render: check STRIPE_WEBHOOK_SECRET + B3 endpoint.
         Refresh the page after a few seconds.

- Billing page not visible in sidebar
      -> You must log in with the ADMIN account.

- Local login gives 500 error
      -> Prisma client mismatch. Run:  cd aba-backend && npx prisma generate
         then RESTART the backend.

E4. WHAT SURVIVES FROM THE OLD FLOW (6 STRIPE_PRICE_* VARS)
-----------------------------------------------------------
Those 6 variables are now LEGACY/optional. Checkout prices come from
the platform pricing config (DB) and are created on demand. The only
remaining use is a fallback: while syncing customer.subscription.up-
dated events, the app tries to map a changed price back to a tier
name — without the vars it simply keeps the plan currently stored.
Skip them unless you later want portal upgrades to auto-rename tiers.

TWO THINGS TO DOUBLE-CHECK BEFORE REAL MONEY
--------------------------------------------
1. BUSINESS NAME — the account is registered under "Naturebylily"
   and that name prints on every customer invoice and email receipts.
   Stripe -> Settings -> Business details -> update it if the ABA
   platform should bill under a different name (or create a separate
   Stripe account for it).
2. PAYOUTS — a bank account must be connected for the money to reach
   you. Stripe -> Payments -> Bank accounts (or Balances -> Set up
   payouts) -> add your UAE bank account.
   Fees: UAE domestic cards ≈ 2.9% + AED 1 per transaction (check the
   current rate in the Dashboard before setting customer prices).
